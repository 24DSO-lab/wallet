# Адаптер Ethereum (ETH и USDC)

Реализует `ports.ChainAdapter` для сети Ethereum: два актива, ETH и USDC
(ERC-20), один общий адрес (`m/44'/60'/0'/0/0`). Ключей в пакете нет: подпись
делает Keystore по дайджесту, который отдаёт `Prepare`.

Зона Dev 5. Пакет не создаёт `http.Client` и не тянет новых зависимостей:
Keccak-256, RLP и восстановление отправителя написаны здесь на стандартной
библиотеке и `internal/hd/secp256k1`.

## Адреса

`ValidateAddress` и `Prepare` работают по одним правилам. Ethereum-адрес
одинаков в профилях main и test, поэтому профиль на проверку не влияет.

| Вход | Решение |
| --- | --- |
| Не `0x` + 40 hex-цифр (нет префикса, `0X`, пробелы, другая длина) | Отклоняется, `invalid_address` |
| Смешанный регистр, контрольная сумма EIP-55 неверна | Отклоняется, `invalid_address` |
| Смешанный регистр, контрольная сумма верна | Принимается без предупреждений |
| Все буквы одного регистра или букв нет | Принимается, `Prepare` добавляет предупреждение `no_checksum_address` |
| Нулевой адрес `0x00…00` | Отклоняется: это сжигание средств |

**Почему адрес в одном регистре не отклоняется, а предупреждает.** Так пишут
многие биржи и обозреватели, и отказ лишил бы пользователя возможности
отправить на такой адрес вообще. Но опечатку в нём ничто не поймает, поэтому
принимать его молча нельзя: экран отправки показывает предупреждение, а
пользователь видит адрес целиком. Форма из заглавных букв и форма из
строчных неотличимы от адреса с контрольной суммой, которая по случайности
состоит из букв одного регистра, поэтому обе трактуются как «суммы нет».

`ValidateAddress` возвращает только `error` (контракт порта), предупреждение
идёт отдельно, через `Prepared.Warnings`.

## Keccak-256

`golang.org/x/crypto/sha3` не входит в vendor, а загрузка модулей закрыта;
стандартный `crypto/sha3` даёт только NIST SHA3-256 (паддинг `0x06`), Ethereum
использует исходный Keccak-256 (паддинг `0x01`). Поэтому `keccak.go` содержит
собственную реализацию (около 60 строк). Проверки:

- перестановка Keccak-f[1600] и разбиение на блоки сверяются со стандартной
  библиотекой для длин от 0 до трёх блоков (разница только в байте паддинга);
- паддинг Ethereum сверяется с известными значениями: хэш пустой строки, `abc`,
  селекторы ERC-20 `transfer(address,uint256)` и `balanceOf(address)`;
- адреса приватных ключей 1, 2 и 3 и векторы EIP-55.

Как только `x/crypto/sha3` можно будет подключить, файл заменяется вызовом
`sha3.NewLegacyKeccak256` отдельным PR с обоснованием.

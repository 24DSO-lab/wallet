# Gate 5 — восстановление и обкатка

Статус: **OPEN — требуется восстановление на чистом профиле/установке**.

Проверяются два независимых способа восстановления: повторный импорт seed
и восстановление встроенного backup. Успешный unit-тест архива не доказывает,
что пользователь сможет восстановить кошелёк после потери рабочего профиля.

## Граница безопасности

- Использовать только отдельный тестовый кошелёк и тестовые сети.
- Не записывать seed, приватные ключи, пароль, BIP39 passphrase, keystore или архив в репозиторий.
- Seed вводить только в локальное приложение на чистом тестовом профиле.
- Не использовать mainnet-средства; mainnet остаётся заблокированным.

## Предусловия

- [ ] Gate 1 имеет технический PASS и явную приёмку владельца.
- [ ] Gate 2 закрыт сверкой балансов и истории.
- [ ] Gate 3 закрыт тестовыми отправками.
- [ ] Используется точный SHA сборки, для которой зелёные CI, Windows Wails build и Playwright.

## A. Проверка восстановления из seed

- [ ] Создать тестовый кошелёк с 12 или 24 словами и записать seed офлайн.
- [ ] Если используется BIP39 passphrase, записать её отдельно и проверить, что приложение её не сохраняет.
- [ ] Зафиксировать публичные BTC receive/change, ETH и TRON адреса; seed и passphrase в протокол не включать.
- [ ] На отдельной чистой установке или в новом Windows-профиле импортировать seed с тем же вариантом passphrase.
- [ ] Сверить BTC account/receive адреса и ETH/TRON адреса с исходным кошельком.
- [ ] Обновить активы и историю; сверить найденные балансы и txid с тестовыми обозревателями.
- [ ] Проверить, что неверная passphrase выводит другой набор адресов и не перезаписывает исходный профиль.

## B. Проверка встроенной резервной копии

- [ ] В исходном тестовом профиле создать backup через Settings, подтвердив пароль keystore.
- [ ] Убедиться, что рядом с ZIP создан файл с расширением .sha256.
- [ ] Скопировать ZIP и checksum на отдельный тестовый носитель/каталог, не оставляя единственную копию рядом с исходным профилем.
- [ ] Установить приложение в чистый Windows-профиль или подготовить чистый test data directory.
- [ ] Запустить Restore Backup, выбрать архив и ввести пароль keystore.
- [ ] Убедиться, что восстановленный профиль разблокируется, список кошельков совпадает, а BTC/ETH/TRON адреса совпадают с исходными.
- [ ] Обновить все активы; сверить баланс и историю с обозревателями.
- [ ] Создать новую резервную копию из восстановленного профиля и проверить её checksum.

## C. Отрицательные сценарии

- [ ] Неверный пароль backup не заменяет рабочие данные.
- [ ] Отсутствующий checksum sidecar отклоняется до замены данных.
- [ ] Изменённый архив с прежним checksum отклоняется.
- [ ] Повреждённый ZIP, дублированные записи и неизвестные пути отклоняются.
- [ ] Ошибка открытия восстановленной БД приводит к rollback исходного профиля; оба набора данных остаются доступными для восстановления.
- [ ] Отмена до начала атомарной замены не повреждает рабочий профиль.
- [ ] После восстановления приложение можно закрыть и открыть повторно без потери данных.

# Gate 3 — тестовые отправки

Статус: **OPEN — реальные тестовые отправки ещё не подтверждены**.

Unit-тесты подписи, сериализации и проверки черновиков не заменяют отправку
через приложение с настоящим keystore и последующую проверку в обозревателе.
Все действия выполняются только в тестовых сетях. Mainnet остаётся заблокирован.

## Граница безопасности

- Использовать отдельный тестовый кошелёк, не содержащий mainnet-средств.
- Перед каждой отправкой проверить профиль test, сеть, актив и адрес получателя.
- Для BTC использовать Bitcoin testnet, для ETH/USDC — Sepolia, для USDT — TRON Nile.
- Для USDC нужен ETH на газ; для USDT нужен TRX на Energy/Bandwidth и комиссию.
- TRX в v1 является комиссионным активом; отправка TRX из приложения не входит в объём v1.
- Не передавать seed, приватные ключи, пароли и passphrase в логи, скриншоты или репозиторий.

## Предусловия

- [ ] Основной CI и расширенные проверки зелёные на точном SHA проверяемой сборки.
- [ ] Создан тестовый кошелёк в приложении, keystore разблокируется штатным паролем.
- [ ] Адреса отправителя сверены с тестовыми сетями и записаны в локальный протокол приёмки.
- [ ] На кошельке есть небольшие тестовые суммы и отдельный запас комиссионной монеты.
- [ ] Адреса получателя принадлежат отдельному тестовому кошельку пользователя.

## Матрица обязательных отправок

| Актив | Сеть | Что проверяется | TxID / ссылка | Итог |
| --- | --- | --- | --- | --- |
| BTC | Bitcoin testnet | P2WPKH, UTXO, комиссия, сдача, broadcast и подтверждение | — | PENDING |
| ETH | Ethereum Sepolia | EIP-1559, nonce, gas, подпись и подтверждение | — | PENDING |

## Процедура для каждого актива

- [ ] Обновить актив и комиссионный баланс; убедиться, что данные не помечены как устаревшие.
- [ ] Подготовить отправку на небольшую тестовую сумму.
- [ ] На экране подтверждения сверить сеть, актив, полный адрес, сумму, комиссию, монету комиссии и итог.
- [ ] Подтвердить операцию паролем keystore (и BIP39 passphrase, если она задана).
- [ ] Записать txid, время UTC, сумму и комиссию; открыть txid в соответствующем обозревателе.
- [ ] Убедиться, что обозреватель видит транзакцию, затем дождаться принятого приложением статуса подтверждения.
- [ ] Обновить кошелёк и проверить, что история содержит ровно одну исходящую запись с правильными суммой, контрагентом, комиссией и статусом.
- [ ] Сверить остаток и комиссию с обозревателем после подтверждения.
- [ ] Перезапустить приложение и убедиться, что статус не откатился и дубль не появился.

## Отрицательные и восстановительные сценарии

- [ ] Неверный формат/сеть адреса отклоняются до подписи.
- [ ] Недостаточный баланс актива или комиссионной монеты отклоняется до подписи.
- [ ] Повторное подтверждение одного draft не создаёт вторую транзакцию.
- [ ] При таймауте broadcast приложение сохраняет recovery record, показывает неопределённый результат и блокирует повторную отправку до reconciliation.
- [ ] После восстановления провайдера reconciliation находит исходный txid и снимает блокировку только после достоверного статуса.
- [ ] Ошибка индексатора истории не затирает последний корректный баланс/историю.
- [ ] Для Bitcoin отдельно выполнен RBF acceptance по документу docs/BITCOIN-RBF-TESTNET-ACCEPTANCE.md.
- [ ] Для TRON получен настоящий ответ Nile и сохранён безопасный fixture по процедуре internal/chain/tron/README.md; секреты и API-заголовки в fixture не включать.

## Протокол результата

Заполнять только публичные данные. Не добавлять seed, приватные ключи, пароли,
passphrase, содержимое keystore или сырые подписанные payload.

| Поле | Значение |
| --- | --- |
| Дата/время UTC | — |
| Commit SHA | — |
| Версия приложения / Go / Wails | — |
| Проверяющий | — |
| Профиль | test |
| BTC txid и explorer URL | — |
| ETH txid и explorer URL | — |
| USDC txid и explorer URL | — |
| USDT txid и explorer URL | — |
| Результат сверки балансов | — |
| Результат сверки истории | — |
| Ошибочные сценарии | — |
| Итог | PENDING |

**PASS** допускается только после подтверждения всех четырёх отправок обозревателями,
корректной истории и балансов, а также отрицательных сценариев. Тестовые монеты
не имеют денежной стоимости. До PASS mainnet не включать.
